# i18n — Système de langue (FR / EN / AR + RTL)

Rend les boutons **FR / EN / AR** fonctionnels sur **toutes les pages**. FR par défaut, EN et
**AR complets**. L'arabe bascule l'interface en **RTL** (sens posé sur `<html dir>` par le layout).

## Architecture

- **`lib/i18n/config.ts`** — `Locale = fr|en|ar`, `ACTIVE_LOCALES = [fr, en, ar]`, cookie `app-locale`, `dir()`.
- **`lib/i18n/dictionary.ts`** — dictionnaire plat `{ 'clé': { fr, en, ar? } }` + `translate(locale, key, vars)`
  (interpolation `{var}`). `ar` est **optionnel** : une clé sans arabe retombe sur le français (résilience +
  les écrans futurs peuvent n'ajouter que `{ fr, en }`). Point d'insertion : `// i18n:append-here`.
- **`lib/i18n/server.ts`** — `getServerLocale()` / `getServerT()` (lecture du cookie via `next/headers`)
  pour les **composants serveur** (landing, auth shell, dashboard).
- **`contexts/LocaleContext.tsx`** — `LocaleProvider(initialLocale)` + `useT()` / `useLocale()` pour les
  **composants clients**. `setLocale` écrit le cookie puis `router.refresh()` → re-render serveur (lang/dir du
  `<html>` + landing/auth) ET client (via le state du contexte). Pas de désync à l'hydratation (initialLocale serveur).
- **`components/boutique/LanguageSwitcher.tsx`** — switcher fonctionnel FR/EN/AR (les 3 basculent la langue).
  Utilisé dans `ScreenTopActions`, `TopBar`, `AuthShell`, landing header.
- **`app/layout.tsx`** — `async`, lit la langue, pose `<html lang dir>`, enveloppe avec `LocaleProvider`.

## Périmètre de traduction (frontière données / chrome)

- **Traduit** (vocabulaire UI) : menus, titres/sous-titres, libellés KPI, en-têtes de tableaux, boutons,
  placeholders, toasts, états vides, **statuts** (En stock/Rupture, Payée/En attente, Remboursé/Dû…),
  **moyens de paiement** (Espèces→Cash…), **périodes**, **rôles** (Patron→Owner…), sections de réglages.
- **NON traduit** (= données saisies par l'utilisateur) : noms de produits/clients, **catégories**
  (Alimentation, Textile…), unités d'alerte stock (sacs, boîtes), montants, dates des fixtures. C'est volontaire :
  dans la vraie appli, ces valeurs viendront de la base et seront ce que le commerçant a saisi.

## Couverture

Chrome partagé (sidebar, top bars, switcher) · Landing · Connexion/Inscription/Vérification ·
Dashboard · Vendre · Ventes · Stock · Créances · Dépenses · Documents · Rapports · Paramètres.
Vérifié : format/lint/typecheck OK ; rendu **EN et AR** confirmés (cookies `app-locale=en` / `=ar`),
chaque surface en `lang="ar" dir="rtl"`, FR par défaut en `dir="ltr"`.

## Ajouter une traduction

1. Ajouter la clé dans `dictionary.ts` (avant `// i18n:append-here`) : `'mon.cle': { fr: '…', en: '…', ar: '…' }`
   (`ar` optionnel — sans lui, l'arabe retombe sur le français).
2. Composant client : `const t = useT()` puis `{t('mon.cle')}`. Composant serveur : `const { t } = await getServerT()`.
3. Interpolation : `t('x', { name })` avec la clé `'… {name} …'`.

## RTL (mise en page arabe)

Le sens d'écriture est posé sur `<html dir>` par le layout via `dir(locale)`. Flexbox suit le sens
automatiquement (la sidebar passe à droite, les colonnes s'inversent). Les utilitaires Tailwind **physiques**
ne se retournent pas seuls — ils ont été convertis en **logiques** : `ml-/mr-→ms-/me-`, `pl-/pr-→ps-/pe-`,
`border-l/r→border-s/e`, `text-left/right→text-start/text-end`, `left-/right-→start-/end-`. Une icône
directionnelle (flèche « voir tout le stock ») utilise la variante `rtl:rotate-180`.
**À l'ajout d'un écran** : préférer d'emblée les classes logiques pour rester RTL-safe.

### Police arabe (Tajawal)

L'arabe utilise **Tajawal** (police arabe moderne) chargée via `next/font` dans `app/layout.tsx`
(`--font-tajawal`). `globals.css` la branche uniquement en arabe :
`html[lang='ar'] { --font-body / --font-headings: var(--font-tajawal), … }`. Le FR/EN reste sur DM Sans.
Aucun composant ne change — les utilitaires `font-body` / `font-headings` lisent la variable surchargée.
